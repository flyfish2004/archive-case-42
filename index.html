02

Как выполнен анализ

SHA-256 позволяет выделить группы. Прямое сравнение байтов отдельно подтверждает равенство содержимого. Окончательный вывод опирается на обе проверки.

  1. 1Прочитать ZIP

    Проверить структуру, распаковать записи и сверить CRC-32.

  2. 2Сгруппировать

    Вычислить SHA-256 исходных байтов каждого файла.

  3. 3Перепроверить

    Независимо сгруппировать файлы прямым сравнением байтов.

  4. 4Найти изменения

    Сопоставить отличающиеся файлы с выбранным эталоном.

#Проверка через SHA-256

Для каждого файла вычислен 256-битный хеш. Получены два значения: одно у 999 файлов, второе — у file_0042.txt.

Результат2 группы: 999 + 1

=Независимая побайтовая проверка

Файлы сгруппированы по полным последовательностям байтов без использования хешей. Состав обеих групп совпал с первой проверкой.

РезультатТе же 2 группы: 999 + 1

CRC-32 проверяет целостность распакованных записей, SHA-256 — их цифровые отпечатки, прямое сравнение — фактическое равенство содержимого. Эти проверки решают разные задачи.

Проверка содержимого

999 файлов содержат 3. и первые 1000 десятичных знаков π, обрезанных без округления.

Число вычислено по формуле Чудновских и алгоритму Гаусса—Лежандра. Оба результата полностью совпали с основной группой.

В изменённом файле заменены 40-я и 41-я цифры после точки.

По одним ASCII-символам нельзя определить исходную кодировку сохранения. Здесь установлена совместимость с UTF-8, а не история создания файлов.

Как повторить исследование test1.zip

Распакуйте материалы. Нужен Python 3.8+, внешние библиотеки не требуются. Эти два скрипта предназначены для проверки test1.zip.

Хеши, сравнение байтов, формула Чудновских:

python analyze.py test1.zip --output report.json

Группировка полных bytes, алгоритм Гаусса—Лежандра:

python verify.py test1.zip --output independent-report.json

Дополнительные проверки загруженных файлов

Исходные байты не нормализуются. Метаданные и SHA-256 всех файлов включены в отчёт.

ФайлБайтДекодированиеBOMCRLF / LF / CRПробелы / TAB

JSON содержит все группы и сравнения с выбранным эталоном. Без эталона в отчёте будут группы и метаданные. CSV содержит метаданные каждого файла.

Возможности и ограничения анализатора
  • Учитываются все файлы, включая бинарные. Папки в количество файлов не включаются.
  • Текст: строгий UTF-8 или UTF-16 с BOM. Для других кодировок доступно сравнение байтов в HEX.
  • Текстовые позиции считаются с 1, по кодовым точкам Unicode; смещения байтов — с 0. Пробелы, TAB и переводы строк показаны явно.
  • Максимальный размер одного распакованного файла — 5 МиБ. Лимиты контролируются до и во время распаковки.
  • Для больших или сильно различающихся файлов выравнивание может быть ограничено. Такие диапазоны отмечаются явно; группировка и CRC остаются точными.
  • При отсутствии большинства эталон выбирает пользователь. Отличие не означает, что файл повреждён или ошибочен.
